# Roadmap

Shipped today: this website and its demos, which together are an **in-browser solver** — TypeScript implementations of the governing equations, computed client-side with no server behind them, at demo scale in one or two dimensions on fixed configurations rather than as a general-purpose package. It covers Scharfetter–Gummel fluxes with damped Newton for Poisson–Nernst–Planck, Tikhonov-regularised NNLS for DRT, RSA microstructure generation with Laplace tortuosity, an explicit phase-field dendrite model, Butler–Volmer kinetics, and a single-particle discharge, and is covered by unit tests in `tests/`. Planned: the Python solver package, which would port the same equations onto an autodiff core so that one Jacobian $J = \partial R/\partial u$ serves time stepping, impedance, and design sensitivities. None of that Python code exists in this repository yet.

Every item below carries a status badge. "Shipped" means you can run it in your browser right now. "In progress" means code exists and is being ported or extended. "Planned" and "research" mean exactly what they say: not built yet.

## The MVP build order

The Python MVP is scoped as five stages. The order is not decoration — each stage consumes the residuals and Jacobian structure the one before it built, which is why they cannot sensibly be done in parallel. No stage carries a date: this is a side project, and a promised date I miss is worth less than a status badge that stays accurate.

1. **Stage 1 — 1D transport core.** The Poisson–Nernst–Planck system in one dimension: Scharfetter–Gummel exponential-fitting fluxes on a finite-volume grid, solved implicitly with a damped Newton iteration. These numerics already run in the [double-layer demo](/Electrochemical-Cell-Simulator/demos/#demo-double-layer); the Python port onto the autodiff core is in progress.
   <StatusBadge status="shipped" label="browser demo" /> <StatusBadge status="planned" label="Python port: planned" />

2. **Stage 2 — Butler–Volmer coupling and thermal block.** Butler–Volmer kinetics as the boundary condition linking electrode potential to interfacial flux, plus an energy balance so overpotential heat feeds back into temperature-dependent parameters. The kinetics are live in the [Butler–Volmer demo](/Electrochemical-Cell-Simulator/demos/#demo-butler-volmer); the thermal block is in progress.
   <StatusBadge status="shipped" label="kinetics in browser" /> <StatusBadge status="planned" label="thermal block: planned" />

3. **Stage 3 — frequency-domain EIS and DRT.** Impedance spectra and their inversion to a distribution of relaxation times by Tikhonov-regularised NNLS run in the [impedance demo](/Electrochemical-Cell-Simulator/demos/#demo-impedance). The full Jacobian-based path — solving $(i\omega M - J)\hat{u} = \hat{b}$ around a Newton-converged operating point — needs the autodiff core and ships with the Python package.
   <StatusBadge status="shipped" label="browser demo" /> <StatusBadge status="planned" label="Jacobian EIS: planned" />

4. **Stage 4 — phase-field dendrites and microstructure.** Explicit phase-field dendrite growth (the animation on the landing page is the in-browser solver computing live, not a video) and RSA-packed electrode microstructures whose tortuosity comes from a Laplace solve. Both run in the browser: [dendrite demo](/Electrochemical-Cell-Simulator/demos/#demo-dendrite), [microstructure demo](/Electrochemical-Cell-Simulator/demos/#demo-microstructure).
   <StatusBadge status="shipped" label="browser demo" /> <StatusBadge status="planned" label="Python port: planned" />

5. **Stage 5 — validation suite and docs.** Gouy–Chapman, Cottrell, and method-of-manufactured-solutions checks run live on the [validation page](/Electrochemical-Cell-Simulator/validation/), comparing the browser solvers against exact analytic results. The PyBaMM P2D comparison has not yet been run and will not be quoted until it has.
   <StatusBadge status="shipped" label="analytic checks" /> <StatusBadge status="planned" label="PyBaMM P2D: not yet run" />

## The longer arc

Past the MVP, the plan follows the same spine — one residual, one Jacobian — into harder territory. None of this is built.

- **Concentrated-solution transport** <StatusBadge status="planned" /> — replace the dilute Nernst–Planck closure with concentration-dependent transport properties for battery electrolytes where the dilute assumption breaks down.
- **Chemo-mechanics and the fracture–SEI loop** <StatusBadge status="research" /> — couple intercalation stress to particle fracture and SEI growth on freshly exposed surface, closing the capacity-fade feedback loop.
- **Gas evolution for electrolysers** <StatusBadge status="planned" /> — bubble coverage and gas-phase transport at gas-evolving electrodes, and their effect on active area and ohmic drop.
- **PINN and DeepONet surrogates with ONNX export** <StatusBadge status="research" /> — train neural surrogates on solver trajectories and export them to ONNX so fast inference does not require the full solver.
- **Bayesian inverse design** <StatusBadge status="research" /> — infer cell parameters from measured impedance and cycling data with full posterior distributions, using adjoint gradients from $J^\top \lambda = -\partial Q/\partial u$.
- **Uncertainty quantification** <StatusBadge status="planned" /> — Sobol sensitivity indices and polynomial-chaos expansions to propagate parameter uncertainty through cell-level predictions.

## Following the project

The repository is private while the solver core is being built, so there is no public issue tracker yet and no source to read. That makes this page the status of record: the badges above are what I believe is true, and they are updated as items move. The one place they are checked against something other than my own judgement is the [validation page](/Electrochemical-Cell-Simulator/validation/), where the analytic comparisons recompute in your browser on every visit — a broken claim breaks visibly there.

When the repository is published, this section becomes a link to it and to its issue tracker, and the tracker takes over as the source of truth. Until then, corrections and questions go to <ObfuscatedEmail />.
